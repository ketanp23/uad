WP 01
Departure · the learning unit

Artificial Neural Networks

An artificial neural network is a stack of simple units that together approximate a function — here, image → meaning. Each neuron takes inputs, multiplies them by learned weights, adds a bias, and passes the sum through a non-linear activation. Stack neurons into layers and the network learns, by example, to map drone pixels to labels.

One neuron. output = φ(w₁x₁ + w₂x₂ + … + b), where φ is a non-linearity. Weights and bias are learned by gradient descent: run a forward pass, measure the loss, back-propagate the error, nudge every weight down its gradient, repeat for many epochs.

Forward pass

Inputs flow layer by layer. Each layer is a matrix multiply plus a bias plus an activation. Early layers capture crude patterns; deeper layers combine them into abstract concepts. The final layer outputs a prediction — a class score, a box, a per-pixel label.

Learning (back-propagation)

A loss function scores how wrong the output is. Back-propagation applies the chain rule to get each weight's share of that error; the optimiser (SGD, Adam) steps the weights downhill. Too many steps on too little data and the net memorises instead of generalising — overfitting.

  • Activation functions — Sigmoid (0–1, saturating), Tanh (−1–1), ReLU (max(0,z), the modern default: cheap, non-saturating).
  • Loss — cross-entropy for classification, regression losses for boxes. The thing gradient descent minimises.
  • Hyper-parameters — learning rate, batch size, epochs, network depth/width. Set by you, not learned.
  • Generalisation — validation accuracy on unseen data is what matters; the gap to training accuracy is overfitting.
Exam line — A single neuron (perceptron) can only separate data with a straight line. Non-linearly-separable problems (the classic XOR) need a hidden layer and a non-linear activation. Depth + non-linearity is what gives networks their power. Try the XOR dataset in the playground and watch one neuron fail.

WP 02
Climb · the vision workhorse

Convolutional Neural Networks

A plain network would need a separate weight for every pixel — millions, and none shared. A CNN instead slides small kernels across the image, reusing the same weights everywhere. This gives local connectivity, parameter sharing and translation invariance: a wheel looks like a wheel wherever it appears in the frame.

Convolution. A k×k kernel slides over the input; at each position it computes a weighted sum, producing one pixel of a feature map. Many kernels → many feature maps. Stack conv → activation → pooling blocks and features grow from edges to textures to parts to whole objects.

Kernels

Learned filters. Early ones become edge/colour detectors; deeper ones respond to textures and object parts. You never hand-design them — training does.

Stride & padding

Stride is the step between windows (larger = smaller output). Padding rings the input with zeros so the output can keep the input's size ("same").

Pooling

Max-pool takes the strongest response in each 2×2 block, shrinking the map and adding a little translation tolerance.

output size = ⌊(W − K + 2P) / S⌋ + 1   # W input, K kernel, P padding, S stride
Exam line — The two ideas that make CNNs work on images are local receptive fields and parameter sharing: the same small kernel is applied everywhere, so the network has few parameters and detects a pattern regardless of position.

WP 03
En route · the task

Object Detection

Object detection outputs, for every object in a frame, a class label and a bounding box with a confidence. It sits above classification (whole-image label) and below segmentation (per-pixel label). Unit III covered the metrics and detector families; here we frame detection as a deep pipeline and build toward vehicle detection, segmentation and avoidance.

  • Backbone — a pretrained CNN (ResNet, Darknet, EfficientNet) that turns pixels into feature maps.
  • Neck / FPN — fuses fine and coarse maps so objects of every size have good features.
  • Head — predicts class scores and box offsets, either densely (one-stage) or from proposals (two-stage).
  • Anchors vs anchor-free — predict boxes relative to preset priors, or predict points/sizes directly.
Bridge from Unit III — IoU, precision/recall, AP/mAP and NMS from the previous unit are assumed here. This unit is about the learned machinery inside the backbone and head, and the UAV tasks built on top.
WP 04
Cruise · learned detectors

Deep-Learning-based Object Detection

Deep detectors replace hand-crafted features with a CNN trained end-to-end, and read objects off a feature pyramid so a single network handles a 4-pixel person and a 200-pixel truck at once. The two families — accurate two-stage (Faster R-CNN) and real-time one-stage (YOLO, SSD, RetinaNet) — both live on this pyramid.

Two-stage · accuracy propose → refine

A region-proposal network suggests candidate boxes; a second head classifies and tightens each. More compute, higher accuracy, better on small and crowded targets — the offline / ground-station choice.

One-stage · speed dense, single pass

One dense head predicts every box in a single forward pass. Real-time on modest hardware — the onboard choice. RetinaNet's focal loss closed much of the old accuracy gap.

UAV note — Altitude shrinks everything, so small-object recall dominates. Fixes: keep input resolution high, tile large frames, add fine pyramid levels, and augment with scale jitter. Explore which level catches which object below.

WP 05
Descent · the old way

Conventional Vehicle Detection

Before deep learning, a vehicle detector was a hand-crafted feature plus a classical classifier plus a search strategy. Engineers designed features that fired on vehicle-like gradients; a sliding window or a motion cue proposed where to look; an SVM or boosted cascade decided yes/no.

Appearance · HOG / Haar + SVM

HOG bins edge orientations into cells; Haar features sum intensity differences; LBP encodes local texture. A sliding window scans an image pyramid and an SVM or AdaBoost cascade classifies each patch. Effective in constrained views, expensive to scan.

Motion · background subtraction

For moving vehicles, model the static background and flag pixels that change (frame differencing, Gaussian mixtures), or use optical flow. Cheap and label-free — but a moving UAV platform makes the "background" move too, breaking the assumption.

  • Features — HOG, Haar-like, LBP, SIFT/SURF key-points. Fixed formulas, no learning.
  • Classifiers — linear/kernel SVM, AdaBoost cascades (Viola–Jones style).
  • Search — sliding window over an image pyramid; background subtraction / optical flow for motion.
  • Cost — thousands of windows per frame; tuned per scene; degrades off its design conditions.
Exam line — Conventional detectors are brittle: sensitive to rotation, scale, illumination and occlusion, and they need per-scene tuning. The nadir aerial view and platform motion are especially hard. This brittleness is exactly what deep learning removed. See it in the HOG descriptor below and the robustness test in the next leg.

WP 06
Approach · the deep way

Deep-Learning-based Vehicle Detection

Modern UAV vehicle detection uses a CNN detector — Faster R-CNN, YOLO, SSD, RetinaNet — that learns vehicle appearance end-to-end from data. Features are discovered, not designed, so the detector tolerates rotation, lighting and partial occlusion that wreck hand-crafted pipelines, and it generalises across scenes.

Why deep wins

Learned features are invariant where hand-crafted ones are brittle; one network does feature + classify + localise jointly; accuracy and recall on messy aerial imagery are far higher. Given labelled data and a GPU, it is simply better.

Aerial-specific tricks

Oriented bounding boxes fit vehicles at any heading; tiling splits huge frames so small cars survive downsampling; scale/rotation augmentation and aerial datasets (VisDrone, UAVDT, DOTA) close the domain gap.

WP 07
Level · per-pixel understanding

Segmentation

Segmentation labels the image at the pixel level. Semantic segmentation gives every pixel a class (road, vegetation, vehicle, building); instance segmentation additionally separates each object; panoptic does both at once. For UAVs this powers land-cover and crop mapping, road extraction, and free-space detection for safe landing.

Semantic · instance · panoptic

Semantic = class per pixel, but all vehicles share one label (uncountable). Instance = a separate mask and id per object (countable) but ignores "stuff" like road. Panoptic unifies both: every pixel gets a class and, for things, an instance id.

Architectures

FCN made networks fully convolutional; U-Net adds an encoder–decoder with skip connections to recover detail; DeepLab uses atrous convolution for wide context; Mask R-CNN adds a mask branch to Faster R-CNN for instances.

  • Encoder–decoder — downsample to understand, upsample (transposed conv) to place labels back at full resolution.
  • Skip connections — feed fine encoder detail into the decoder so edges stay crisp.
  • Metric — mean IoU (mIoU): average per-class intersection-over-union of predicted vs true masks.
  • UAV uses — precision agriculture, land cover, road/water mapping, landing-zone free-space.
Exam line — Distinguish the three: semantic (class per pixel), instance (per-object masks), panoptic (both). Onboard UAVs often run a lightweight semantic model for free-space and obstacles because full instance segmentation is compute-heavy. Toggle the modes below.

WP 08
Manoeuvre · don't hit anything

Obstacle Detection & Avoidance

Avoidance is a two-step loop: perceive obstacles (recover depth / occupancy) then plan a safe path. Depth comes from stereo disparity, learned monocular depth, LiDAR, ultrasonic or optical flow; planning ranges from fast reactive fields to deliberate search.

Sensing depth

Stereo triangulates disparity between two cameras; monocular nets predict depth from one image (cheap, learned); LiDAR measures range directly; optical flow gives time-to-collision from image motion. Output: a depth map or an occupancy grid.

Avoidance: reactive vs planned

Reactive methods (potential fields, Vector Field Histogram) steer instantly from local sensing — fast but can trap in local minima. Deliberative planners (A*, RRT) search a map for a guaranteed route — safer, more compute, needs a map.

  • Depth cues — stereo disparity, monocular depth nets, LiDAR/ultrasonic, optical-flow time-to-collision.
  • Representation — depth map, occupancy / cost grid, ESDF distance fields.
  • Reactive — artificial potential fields (attract to goal, repel from obstacles), VFH. Cheap, myopic.
  • Deliberative — A*, D*, RRT/RRT*; complete-ish, higher cost, replans as the map updates.
Exam line — Potential fields are the textbook reactive method: simple, fast, but they can get stuck in a local minimum (a dead-end pocket) where attractive and repulsive forces cancel. Crowd the obstacles in the planner below to reproduce it, then note how a global planner would escape.

WP 09
Final · make it work on little data

Transfer Learning for UAV

Aerial labelled data is scarce and expensive, so we rarely train from scratch. Transfer learning takes a network pretrained on a huge dataset (ImageNet, COCO), keeps its general features, and adapts it to the UAV task — either as a frozen feature extractor or by fine-tuning. The right amount to unfreeze depends on how much data you have and how far your imagery is from the source.

Feature extraction vs fine-tuning

Feature extraction: freeze the backbone, train only a new head — fast, low-data, low risk of overfitting. Fine-tuning: unfreeze some or all layers and continue training at a low learning rate — higher ceiling, needs more data and care.

Domain gap & strategy

Nadir aerial views differ from ground photos, so the top layers often need retraining. Rule of thumb: small + similar → freeze most; large + different → fine-tune deep. Augmentation and domain adaptation shrink the gap; too-low freezing on too-little data overfits.

  • Pretraining — learn general features on a large source dataset once.
  • Freezing — hold early layers fixed (they are generic); train later, task-specific layers.
  • Learning rate — fine-tune with a small LR so pretrained weights aren't wrecked (catastrophic forgetting).
  • Payoff for UAV — usable accuracy from hundreds, not millions, of aerial labels.
Exam line — Transfer learning is essential for UAV vision because aerial datasets are small. Freeze more when data is scarce or similar to ImageNet; fine-tune deeper when data is plentiful or the domain is very different. The simulator below makes the trade concrete.

Revision & Quiz

Quick self-check tap to reveal
What does a single neuron compute, and what is its limitation?
A weighted sum of inputs plus a bias, passed through a non-linear activation. Limitation: alone it can only separate linearly-separable data; non-linear problems (XOR) need hidden layers.
Why do CNNs use parameter sharing?
The same kernel is applied at every position, so a pattern is detected wherever it appears and the number of parameters stays small — giving translation invariance and efficiency versus a fully-connected net.
Why do UAV detectors rely on fine feature-pyramid levels?
From altitude, objects are small; fine, high-resolution levels (P3/P4, small stride) retain the detail needed to detect them, while coarse levels handle rare large objects.
Give two reasons deep vehicle detection beat conventional methods.
Features are learned (invariant to rotation/lighting/occlusion) rather than hand-crafted and brittle; and detection is end-to-end, jointly optimised for accuracy, outperforming HOG/Haar + SVM on varied aerial scenes.
Semantic vs instance vs panoptic segmentation?
Semantic = a class for every pixel (objects of a class merged); instance = a separate mask per object; panoptic = both, every pixel gets a class and things also get instance ids.
What failure mode do potential-field planners have?
Local minima: attractive (goal) and repulsive (obstacle) forces cancel in a pocket and the drone stalls short of the goal. Global planners (A*, RRT) avoid this at higher compute.
When should you freeze most of a pretrained backbone?
When the target aerial dataset is small (and/or similar to the source). Freezing preserves generic features and prevents overfitting; fine-tune deeper only with more data or a larger domain gap.

  • Explain the CNN operations — convolution, activation, pooling — and why parameter sharing suits images.
  • Draw the backbone–neck–head detection pipeline and explain the role of a feature pyramid for UAVs.

Key Takeaways

If you remember only one thing

Deep learning replaced hand-crafted vision with learned features: neurons stack into CNNs, CNNs become detectors and segmenters, and transfer learning adapts them to scarce aerial data. The recurring UAV theme is small objects from altitude and doing useful perception onboard, in real time, without hitting anything.

01

A neuron is a weighted sum + non-linearity

Networks learn weights by gradient descent. One neuron draws a line; depth and non-linear activations let a network learn any boundary.

02

CNNs share weights across the image

Sliding kernels give local receptive fields, parameter sharing and translation invariance — few parameters, features from edges to objects.

03

Detection = backbone → neck → head

A CNN backbone extracts features, an FPN neck fuses scales, a head predicts class + box, NMS dedupes. Everything modern fits this shape.

04

Pyramids catch small objects

Fine, high-resolution levels detect the tiny targets a UAV sees from altitude; keep input resolution high and tile big frames.

05

Conventional detection is brittle

HOG/Haar + SVM with sliding windows or background subtraction work in narrow conditions but break on rotation, light and platform motion.

06

Deep vehicle detection is invariant

Learned, end-to-end features tolerate the variation aerial platforms introduce — the reason UAV vehicle detection went deep.

07

Segmentation labels every pixel

Semantic (class/pixel), instance (per-object masks), panoptic (both). Encoder–decoders (U-Net) and Mask R-CNN are the workhorses.

08

Avoid = perceive depth, then plan

Stereo/monocular/LiDAR give depth; reactive fields are fast but trap in local minima; A*/RRT plan safely with more compute.

09

Transfer learning makes it feasible

Pretrain big, adapt small. Freeze most for tiny aerial datasets; fine-tune deeper with more data or a larger domain gap.

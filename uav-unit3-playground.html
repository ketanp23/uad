WP 01
Departure

The Object Detection Problem

Object detection answers two questions at once for every object in an image: what is it (classification) and where is it (localisation). The output is a set of class-labelled bounding boxes, each with a confidence score. On a UAV this is the perception layer that turns raw video into things a mission can act on — vehicles, people, cattle, cracks, solar panels, a landing pad.

Four vision tasks, one ladder. Classification = one label for the whole image. Classification + localisation = one label plus one box, for a single dominant object. Object detection = many objects, each its own label and box. Segmentation = a class for every pixel (semantic) or every pixel of every instance (instance). Detection is the middle rung and the one this unit lives on.
Why detection is hard
  • Variable count — the number of objects is unknown and changes per frame, so the output size is not fixed.
  • Scale & viewpoint — the same object appears tiny or huge; UAV nadir and oblique views are unlike ground-level training data.
  • Occlusion & clutter — objects overlap, hide behind each other, and blend into busy backgrounds.
  • Localisation vs classification — one head must regress geometry, another must name the class; they are trained together.
  • Real-time budget — onboard, the answer is worthless if it arrives after the aircraft has moved past the scene.
The UAV angle
  • Small objects — from altitude, a person is a handful of pixels; small-object recall is the headline UAV challenge.
  • Dense scenes — crowds, parked cars and orchards pack many boxes into a frame, stressing NMS and anchors.
  • Motion & blur — airframe vibration and forward speed smear fast-moving targets.
  • Edge compute — a Jetson-class board, not a data-centre GPU, sets the model you can actually run.
  • Onboard vs offload — detect live for real-time reaction, or record and run a heavier model on the ground.
Exam line — Do not conflate the tasks. "Object detection labels the whole image" is wrong — that is classification. Detection outputs multiple class-labelled boxes, one per object instance.
WP 02
Geometry

Bounding Boxes

A bounding box is the axis-aligned rectangle that tightly encloses an object. It is the fundamental output geometry of detection — every architecture in this unit ultimately regresses four numbers per object that describe one box.

Three ways to write the same box the four numbers
FormatParametersUsed by
Corner (Pascal VOC)(xmin, ymin, xmax, ymax) — top-left and bottom-right in pixelsPascal VOC, many annotation tools
Centre (YOLO)(xc, yc, w, h) — centre point plus width and height, usually normalised to [0,1]YOLO family
Top-left + size (COCO)(xmin, ymin, w, h) — top-left corner plus width and height in pixelsCOCO dataset & API

Normalising by image width and height makes coordinates resolution-independent — the same label works whether the frame is 640 px or 4K.

Ground-truth vs predicted

A ground-truth box is the human annotation used for training and evaluation. A predicted box is what the model outputs, carrying a confidence / objectness score. Training pushes predicted boxes towards ground truth; evaluation compares the two using IoU (next leg).

Anchor boxes (priors)

Rather than regress a box from nothing, most detectors place anchors — a fixed set of reference boxes at several scales and aspect ratios — at every location on the feature map, then predict small offsets from the nearest anchor. Anchors give the network sensible starting shapes and are central to Faster R-CNN, SSD and early YOLO. Newer anchor-free detectors drop them and predict boxes directly.

Exam line — Know the offset trick: the network does not output raw pixel coordinates, it outputs deltas (tx, ty, tw, th) relative to an anchor. This makes the regression target small and well-behaved.

WP 03
Scoring

Object Detection Metrics

A detector is judged on two things together — did it find the object (localisation) and did it name it correctly (classification). The whole scoring stack is built on one geometric primitive: Intersection over Union.

IoU — Intersection over Union

IoU measures how well a predicted box overlaps a ground-truth box. It is the area they share divided by the total area they cover together. IoU = 0 means no overlap; IoU = 1 means a perfect match.

IoU = area(prediction ∩ ground‑truth) / area(prediction ∪ ground‑truth)

A prediction usually counts as correct only if IoU ≥ a threshold (0.5 is the classic Pascal VOC bar) and the predicted class matches.

Precision & Recall
Precision = TP / (TP + FP) Recall    = TP / (TP + FN)

Precision asks: of the boxes I drew, how many were right? Recall asks: of the objects that were there, how many did I find? Raising the confidence threshold trades recall for precision, and vice-versa — which is exactly what a PR curve plots.

AP & mAP

Average Precision (AP) is the area under the precision–recall curve for one class — a single number summarising the whole precision/recall trade-off. Mean Average Precision (mAP) is the AP averaged over all classes.

  • Pascal VOC — AP at a single IoU = 0.5 (written mAP@0.5).
  • COCO — mAP averaged over IoU 0.50 → 0.95 in steps of 0.05, the stricter modern standard.

Non-Maximum Suppression (NMS)

A detector typically fires several overlapping boxes on the same object. NMS cleans this up: keep the highest-confidence box, discard every other box whose IoU with it exceeds a threshold, and repeat. Without NMS, duplicates inflate false positives and wreck precision.

Speed metric to know: FPS (frames per second) or latency in ms — the axis on which real-time UAV detectors are judged, traded off against mAP.

WP 04
Taxonomy

Object Detection Architectures

Every modern detector splits into the same three parts, and falls into one of two families. Learn this map first — the individual architectures on the following legs are just points on it.

Backbone → Neck → Head
  • Backbone — a CNN (VGG, ResNet, CSPDarknet, EfficientNet) pretrained on classification that extracts a feature map from the image.
  • Neck — feature aggregation across scales, typically a FPN, so both small and large objects are represented well.
  • Head — the prediction layers that output class scores and box offsets. Two-stage detectors have a proposal head plus a refinement head; one-stage detectors have a single dense head.
Two-stage · accuracy

Stage 1 proposes a manageable set of candidate regions likely to contain objects; stage 2 classifies and refines each. More computation, higher mAP, especially on small and overlapping objects. The R-CNN → Fast → Faster line is the canonical example.

One-stage · speed

Skip proposals entirely and predict class-plus-box densely across the image in one pass. Far faster — the basis of real-time detection. YOLO, SSD and RetinaNet live here; RetinaNet's focal loss closed much of the old accuracy gap.

Exam line — The one-line distinction: two-stage = region proposal then classification (accurate, slower); one-stage = direct dense prediction in a single pass (fast, real-time). Everything else is detail.
WP 05
Two-stage · origin

R-CNN

R-CNN (Regions with CNN features, Girshick et al., 2014) was the model that brought deep CNNs to detection. Its idea is simple: propose regions, then run a CNN on each one. It works, but it is slow — and the two legs that follow are the story of fixing that slowness.

The R-CNN pipeline
  • 1 · Region proposals — Selective Search generates ~2000 candidate regions per image.
  • 2 · Warp — each region is cropped and warped to a fixed 227×227 size.
  • 3 · CNN features — a CNN (AlexNet) is run on every warped region to extract a feature vector.
  • 4 · Classify — a set of class-specific linear SVMs score each region.
  • 5 · Refine — a separate bounding-box regressor tightens the box; NMS removes duplicates.
Why it was a breakthrough

It roughly doubled the best detection mAP of its day by replacing hand-crafted features with learned CNN features. It proved that transfer learning — pretrain on ImageNet classification, fine-tune for detection — was the way forward.

Why it was painfully slow
  • 2000 CNN passes — the CNN runs once per region, with no sharing, so a single image takes tens of seconds.
  • Multi-stage training — CNN, SVMs and regressor are trained separately, not end-to-end.
  • Disk-heavy — extracted features are cached to disk, needing hundreds of gigabytes.
  • Fixed proposals — Selective Search is a separate, non-learned, slow pre-step.
Exam line — R-CNN's fatal flaw is redundant computation: the CNN is evaluated ~2000 times per image because each proposal is processed independently. Fast R-CNN fixes exactly this.
WP 06
Two-stage · sharing

Fast R-CNN

Fast R-CNN (Girshick, 2015) makes one decisive change: run the CNN once over the whole image, then reuse that shared feature map for every proposal. The result is roughly an order-of-magnitude speed-up and a single, jointly-trained network.

What changed from R-CNN
  • One CNN pass — the whole image goes through the backbone once, producing a single feature map.
  • RoI pooling — each proposal is projected onto that feature map and pooled to a fixed size, so any-sized region becomes a fixed-length feature — no per-region CNN.
  • Single network, two heads — a softmax classifier and a bounding-box regressor share the backbone.
  • Multi-task loss — classification loss and localisation (smooth-L1) loss are trained together in one step.
  • No disk cache — features are computed on the fly, training is end-to-end from features to output.
Exam line — Fast R-CNN's remaining bottleneck is still Selective Search: proposals come from a separate, hand-designed, CPU-bound algorithm that now dominates the runtime. Faster R-CNN removes it.
WP 07
Two-stage · end-to-end

Faster R-CNN

Faster R-CNN (Ren et al., 2015) removes the last hand-crafted step by learning the proposals too. A small Region Proposal Network (RPN) shares the backbone's features and generates proposals almost for free — making the whole detector a single, end-to-end trainable network.

The Region Proposal Network (RPN)
  • Shared features — the RPN slides over the same feature map the detection head uses; no separate image pass.
  • Anchors — at each location it places k anchor boxes (typically 3 scales × 3 aspect ratios = 9) as reference shapes.
  • Two tiny heads — for each anchor it predicts an objectness score (object vs background) and four box-offset deltas.
  • Top proposals — the highest-scoring anchors, after NMS, become the region proposals fed to the Fast R-CNN detection head.
  • End-to-end — RPN and detector are trained jointly with shared convolutions.

WP 08
One-stage · real-time

YOLO

YOLO — "You Only Look Once" (Redmon et al., 2016) — reframes detection as a single regression problem solved in one forward pass. No proposals, no second stage: the whole image goes through the network once and boxes come straight out. This is what makes real-time UAV detection possible.

How YOLO sees an image
  • Grid — the image is divided into an S×S grid of cells.
  • Per-cell prediction — each cell predicts B bounding boxes, each with a confidence (objectness) score, plus class probabilities for the cell.
  • One tensor out — the whole output is a single tensor produced in one pass; the network is trained end-to-end on a combined localisation + confidence + classification loss.
  • NMS — overlapping boxes are suppressed to leave one box per object.
  • Global reasoning — because it sees the whole image at once, YOLO makes fewer background false positives than region-based methods.

Strengths
  • Speed — one pass, no proposal stage; runs in real time even on modest hardware.
  • Global view — reasons over the whole image, so it confuses background for objects less often.
  • Simple & deployable — a single network, easy to export to edge devices.
Weaknesses & evolution

YOLOv1 struggled with small objects, objects in groups, and unusual aspect ratios — precisely the small, dense targets a UAV sees from altitude. Successive versions (v2/v3 added anchors and multi-scale FPN-style prediction; v4, v5 and later added stronger backbones and training tricks) steadily closed the accuracy gap while keeping the single-shot speed.

Exam line — YOLO's core reframing: detection as a single regression from image pixels straight to box coordinates and class probabilities, evaluated in one pass. That single-pass design is what buys real time.
WP 09
Toolkit

Detectron2

Detectron2 is not a single architecture — it is Facebook AI Research's open-source detection library, built on PyTorch. It packages state-of-the-art detectors (Faster R-CNN, Mask R-CNN, RetinaNet and more) behind a common config and a pretrained model zoo, so you build detectors from parts instead of from scratch.

What Detectron2 gives you
  • PyTorch-native — a ground-up rewrite of the original Caffe2 Detectron, easier to read, extend and debug.
  • Model zoo — pretrained weights and reference configs for many detection and segmentation models.
  • Modular design — swap backbones, necks, heads, RoI logic and losses by editing a config, not the code.
  • Beyond boxes — supports instance segmentation, panoptic segmentation, keypoint / pose and rotated boxes.
  • Training & eval infra — data loaders, augmentation, distributed training, and COCO-style mAP evaluation built in.
Where it sits

Detectron2 is the research-and-production home of the two-stage / R-CNN family (its flagship is Mask R-CNN). It is heavier than a single-file YOLO repo, and typically used for offline or ground-station processing where accuracy and flexibility matter more than onboard latency.

Library vs architecture

A common exam trap: Detectron2 is a framework, YOLO/Faster R-CNN are architectures. You can implement Faster R-CNN inside Detectron2; you cannot compare "Detectron2 vs Faster R-CNN" as if they were the same kind of thing. Ultralytics plays the analogous framework role for the YOLO line.

Exam line — Detectron2 = FAIR's modular PyTorch detection/segmentation library with a model zoo. Name at least one algorithm it ships (Mask R-CNN) and one capability beyond boxes (instance or panoptic segmentation).

Choosing a Detector for a UAV

The whole unit collapses into one engineering decision: for this mission, on this hardware, which detector wins? The answer is the speed–accuracy trade, filtered through where the computation happens.

Approach & landing

Rapid Revision & Self-Check

One-line recall
  • Detection = classification + localisation for every object → a set of class-labelled boxes with confidences.
  • Box formats = corner (x₁,y₁,x₂,y₂), centre (xᶜ,yᶜ,w,h), COCO (x,y,w,h); anchors give reference shapes, network predicts offsets.
  • IoU = overlap ÷ union; a box is a TP if IoU ≥ threshold and the class matches.
  • Precision = TP/(TP+FP); Recall = TP/(TP+FN); AP = area under the PR curve; mAP = mean AP over classes.
  • NMS = keep the top box, drop overlaps above an IoU threshold; removes duplicates.
  • Architecture = backbone → neck (FPN) → head; two families: two-stage (accurate) vs one-stage (fast).
  • R-CNN = Selective Search + CNN per region + SVM; slow (~2000 CNN passes).
  • Fast R-CNN = one shared CNN pass + RoI pooling + multi-task loss; proposals still external.
  • Faster R-CNN = adds the RPN with anchors; proposals learned; end-to-end; basis of Mask R-CNN.
  • YOLO = single-pass regression over an S×S grid → S×S×(B·5+C) tensor; real-time.
  • Detectron2 = FAIR's modular PyTorch detection/segmentation library + model zoo (a framework, not an architecture).
Self-check — tap a question to reveal the answer
Which is NOT part of the detection output for one object?
A pixel-perfect mask. Detection outputs a class label, a bounding box and a confidence score. A per-pixel mask is instance segmentation (e.g. Mask R-CNN), a rung above plain detection.
Define IoU and state the classic acceptance threshold.
IoU = area(intersection) / area(union) of the predicted and ground-truth boxes. The classic Pascal VOC threshold for accepting a detection is IoU ≥ 0.5; COCO averages mAP over IoU 0.50–0.95.
What does mAP measure, and why must you quote the IoU threshold?
mAP is the mean, over all classes, of each class's Average Precision (area under its precision–recall curve) at a given IoU threshold. Because the threshold changes the TP/FP counts, mAP@0.5 and mAP@[.5:.95] are different numbers — always state which.
Why is R-CNN so slow at test time?
It runs the CNN independently on each of ~2000 Selective Search proposals per image — no feature sharing — plus multi-stage training and disk-cached features.
What single change defines Fast R-CNN?
One shared CNN pass over the whole image, then RoI pooling projects each proposal onto the shared feature map to a fixed size — replacing 2000 CNN passes with one, and enabling a single multi-task loss.
What makes Faster R-CNN "faster" than Fast R-CNN?
The Region Proposal Network (RPN) — a small network that shares the backbone's features and generates proposals from anchors, replacing the slow external Selective Search and making the detector end-to-end trainable.
State YOLO's core idea in one sentence.
Treat detection as a single regression over an S×S grid, predicting all boxes, confidences and class probabilities in one forward pass — which is what makes it real-time.
Is Detectron2 an architecture? Explain.
No — it is a library / framework (FAIR, PyTorch) that implements many architectures such as Faster R-CNN, Mask R-CNN and RetinaNet, with a model zoo and config system. You build architectures inside it.
Which detector family fits onboard real-time UAV use, and which fits offline mapping?
Onboard, real-time → one-stage (YOLO) for speed on edge hardware. Offline, accuracy-critical → two-stage (Faster R-CNN via Detectron2). Small-object recall from altitude usually drives the choice.
What does NMS do and why is it needed?
Non-Maximum Suppression keeps the highest-confidence box and discards others overlapping it above an IoU threshold, removing duplicate detections that would otherwise count as false positives.

Arrival · what you carry off the aircraft

Key Takeaways

If you remember only one thing

Object detection is classification plus a box, for every object at once, scored by IoU-based mAP. Two families answer it: the two-stage R-CNN line (propose, then classify — accurate, and it got faster by pulling every external step inside the network) and the one-stage YOLO line (one pass, real-time). Which you fly on a UAV is a speed-versus-accuracy trade decided by where the computation runs.

01

Detection is the middle rung

Classification names the image, localisation adds one box, detection outputs many class-labelled boxes, segmentation labels every pixel. This unit lives on detection — many objects, each its own box and confidence.

02

A box is four numbers, three notations

Corner (x₁,y₁,x₂,y₂), centre (xᶜ,yᶜ,w,h) and COCO (x,y,w,h) describe the same rectangle. Networks predict small offsets from anchor boxes, not raw coordinates.

03

IoU is the root metric

Overlap ÷ union. Everything — TP/FP/FN, precision, recall, AP, mAP — is built on IoU and the threshold you set on it. Always quote the threshold.

04

mAP is the headline score

AP is the area under one class's precision–recall curve; mAP averages it over classes. NMS removes duplicate boxes before scoring; FPS measures the speed you trade against mAP.

05

Every detector is backbone → neck → head

A CNN backbone extracts features, an FPN-style neck fuses scales, and a head predicts classes and boxes. Two-stage adds a proposal head; one-stage uses a single dense head.

06

R-CNN proved CNNs detect — slowly

Selective Search proposes ~2000 regions, a CNN runs on each, SVMs classify. Learned features doubled accuracy but the per-region CNN made it unusably slow.

07

Fast R-CNN shares the backbone

One CNN pass over the whole image, RoI pooling per proposal, a single network with a multi-task loss. Order-of-magnitude faster — but Selective Search is now the bottleneck.

08

Faster R-CNN learns the proposals

The RPN generates proposals from anchors using shared features, replacing Selective Search and making the detector end-to-end. It is the foundation of Mask R-CNN.

09

YOLO looks once

Detection becomes a single regression over an S×S grid, all boxes and classes emitted in one pass. Real-time and globally aware, historically weaker on small, clustered objects.

10

Detectron2 is a toolbox, not a model

FAIR's modular PyTorch library implements Faster R-CNN, Mask R-CNN, RetinaNet and more, with a model zoo and config system, extending to instance and panoptic segmentation.

11

The UAV choice is speed vs accuracy

Onboard and real-time favours a compact YOLO on edge hardware; offline and accuracy-critical favours Faster R-CNN via Detectron2. Small-object recall from altitude usually decides it.
